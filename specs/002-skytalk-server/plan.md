## Summary

The SkyTalk server is a Node.js/TypeScript application built on Express with a tRPC
router as the sole API surface. It exposes typed procedures — queries, mutations, and
real-time subscriptions over WebSocket — to orchestrate two external services: the
OpenWeatherMap API (weather data) and the Anthropic Claude API (conversational AI via
tool use). The `AppRouter` type is exported and imported type-only by the client,
making the server the single source of truth for all client-server contracts.
Structured JSON logging is emitted via pino for every significant operation.

## Technical Context

**Language/Version**: TypeScript 5.x on Node.js 20 LTS
**Primary Dependencies**:

- `express` — HTTP server foundation
- `@trpc/server` — tRPC core; procedure builder and router
- `@trpc/server/adapters/express` — mounts tRPC on Express for HTTP procedures
- `ws` + `@trpc/server/adapters/ws` — WebSocket server for tRPC subscriptions
- `@langchain/core` — LangChain base abstractions (runnables, tools, prompts)
- `@langchain/anthropic` — `ChatAnthropic` class; Claude model integration
- `langchain` — `tool()` helper for defining weather API tools with Zod schemas
- `axios` — OpenWeatherMap REST API calls
- `pino` — structured JSON logging
- `dotenv` — environment variable loading
- `zod` — runtime input validation for tRPC procedure inputs and LangChain tool schemas

**Dev Dependencies**:

- `jest` + `ts-jest` — test runner
- `supertest` — HTTP integration tests for the health procedure
- `@trpc/server` test utilities — call procedures directly without HTTP in unit tests

**Storage**: None — session state held in memory per WebSocket connection
**Testing**: Jest (unit + integration); procedures tested directly via tRPC caller
**Target Platform**: Node.js 20 LTS on Linux (local dev on macOS)
**Project Type**: Web service (backend)
**Performance Goals**: End-to-end query response within 8 seconds (SC-S-001);
health procedure responds within 100ms (SC-S-005)
**Constraints**: OpenWeatherMap free tier (60 req/min); session-only; no database;
location data MUST NOT appear in INFO-level logs
**Scale/Scope**: ~10 concurrent WebSocket sessions (interview/demo scale)

### tRPC Router Structure

```typescript
// src/router/index.ts
export const appRouter = router({
  health:         publicProcedure.query(...)          // Server status
  sendQuery:      publicProcedure.input(z.object({    // User submits a query
                    text: z.string().min(1)
                  })).mutation(...)
  selectLocation: publicProcedure.input(              // Resolve ambiguous location
                    SelectLocationSchema
                  ).mutation(...)
  chatStream:     publicProcedure.subscription(...)   // Real-time event stream
});

export type AppRouter = typeof appRouter;
```

The `chatStream` subscription emits a discriminated union:

```typescript
type ChatEvent =
  | { type: 'loading' }
  | { type: 'message';              payload: Message }
  | { type: 'clarification_needed'; payload: ClarificationPayload }
  | { type: 'error';                payload: { message: string; retryable: boolean } }
```

### AI System Prompt (non-negotiable rules)

The system prompt provided to Claude MUST include:

1. **Empathetic Accuracy**: Always interpret weather data in human terms.
2. **Contextual Relevance**: When the user mentions an activity, provide suitability.
3. **Tone**: Friendly, professional, observant — like a knowledgeable neighbor.
4. **Safety**: For life-threatening events, lead with official safety warnings.
5. **Clarification**: If location is ambiguous, ask before fetching data.
6. **Scope**: Politely redirect non-weather queries.

### LangChain Agent Setup

`aiService.ts` constructs a LangChain tool-calling agent:

```typescript
import { ChatAnthropic } from '@langchain/anthropic';
import { tool } from 'langchain/tools';
import { z } from 'zod';

const llm = new ChatAnthropic({
  model: 'claude-sonnet-4-6',
  streaming: true,         // streams tokens into tRPC subscription
});

const getCurrentWeather = tool(
  async ({ city }) => weatherService.getCurrent(city),
  { name: 'getCurrentWeather',
    description: 'Get current weather for a city',
    schema: z.object({ city: z.string() }) }
);

const getForecast = tool(
  async ({ city, days }) => weatherService.getForecast(city, days),
  { name: 'getForecast',
    description: 'Get N-day weather forecast for a city',
    schema: z.object({ city: z.string(), days: z.number().min(1).max(7) }) }
);

const modelWithTools = llm.bindTools([getCurrentWeather, getForecast]);
```

The agent's streaming output is piped into the `chatStream` tRPC subscription via
an `observable` wrapper. Each streamed chunk emits a `{ type: 'message' }` event.

### tRPC Error Formatting

A custom `errorFormatter` MUST be registered on the tRPC router to strip internal
error details from client-facing responses. The client MUST never receive a raw
stack trace or internal error message — only the user-friendly `message` string.
